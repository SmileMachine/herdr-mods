# Herdr 端口管理方案

状态：设计草案；未实现。日期：2026-11-19。

## 1. 目标与边界

- 保留 Live Ports 的独立状态栏入口、集中列表及进程信息，借鉴 Space Ports 的终端进程树识别和 SSH 本地转发。
- 发现可访问机器上的 TCP 监听端口，按机器展示；尽可能展示地址、端口、进程名、PID、Space、归属依据及状态。权限不足时标记未知，不能承诺发现所有端口或 PID。
- 两种 Space 归属策略可随时切换：按监听进程工作目录 / Git checkout，或按终端进程树。展示策略影响归属，不改变实际端口、进程或转发。
- 可查看所有发现记录并按进程名（文本或正则）、端口和范围等筛选。筛选仅作用于展示，不改变扫描、共享原始结果、进程或已有转发。
- 可选扫描没有 Space 的已添加 machine；默认关闭，避免后台连接用户未选择的机器。机器枚举、远程执行、权限和断连行为先验证，再实现；不支持时明确报告，不伪装成功。
- 可选在 Space 侧栏显示端口，默认关闭。独立面板是主入口；关闭侧栏显示不能影响发现或转发。
- 不做 UDP、远程文件编辑、公开隧道或自动停止服务。默认不自动建立转发。

## 2. 数据与发现

**原始发现、归属、视图筛选、转发状态分层**。一次扫描产生每台机器独立快照，条目包含 machine、监听 host/address、port、PID/进程名（可空）、观察时间，以及工作目录、祖先进程或 TTY 的可用性。键必须区分机器、地址、端口及进程，不能单以端口号去重：同一个端口可由不同机器、不同地址或多个进程持有。IPv4/IPv6 及通配地址必须保留；仅在明确相同监听的情况下折叠展示，不丢原始数据。

本机及启用范围内的远程机器分别并发扫描，限制并发和超时。优先使用可用工具（macOS `lsof`；Linux `lsof` 或 `ss` / `ps`），明确区分命令不存在、退出失败、无权限、空结果及超时；Linux `ss` 没有 PID 时保留可解析的监听记录并标记未知，而不是丢弃。旧快照在机器扫描失败时可保留但标明过期和错误，不能冒充实时数据；恢复成功后替换。进程或 PID 变化后使归属缓存失效，防止 PID 复用及 `cwd` 改变导致旧归属。避免持久化环境变量、命令参数或敏感文件内容。

### 可切换的 Space 归属

- **终端进程树**（建议默认）：从 Herdr terminal shell PID 沿父子关系确定归属；非 Space 的 TTY 进程单独标为其他终端。守护进程脱离终端、权限不足或祖先不可见时为未知/未归属。应区分“确认无关”和“无法判断”。
- **工作目录 / checkout**：将监听进程 cwd 与同机器 Space 的 Git checkout 关联，最深匹配优先。不是 Git checkout、cwd 不可读或多个 Space 指向同一 checkout 时，不得凭空确定唯一归属；应暴露歧义或未归属。不同机器的相同路径不能混淆。

策略可在 GUI 中切换，保存为偏好；若当前快照缺少另一策略的数据，立即触发必要的重新采集，并显示处理中，而不是错误归类。展示归属依据，不让使用者误以为 cwd 归属一定由该 Space 启动。

### 其他终端 / 低端口标记

对每条记录分别计算 `terminalRelated: yes/no/unknown` 和 `port < 32768`。Space Ports 的“其他终端且小于 32768”只是一个**可组合的快捷筛选**，不是发现范围，也不是安全边界。默认展示全部可发现记录；未知记录在筛选启用时的行为要在 UI 明示，不将未知标成否。

## 3. 配置与 UI

主面板为状态栏入口和弹层，按 machine 分组；Space 归属、其他终端和其他进程可清楚区分，不在多个 Space 重复伪装成各自端口。按权限可用性展示名称、PID、地址、端口、归属和转发状态。设备离线、权限不足、无结果与筛选无结果需分别提示。

提议的可持久化配置（具体存储与 UI 在实现前验证 Herdr API）：

| 选项 | 建议默认 | 行为 |
| --- | --- | --- |
| 归属策略 | 终端进程树 | 可切换为工作目录 / checkout |
| 扫描无 Space 的已添加 machine | 关 | 开启后尽力发现在线机器；可随时关闭 |
| Space 侧栏端口 | 关 | 只改变侧栏展示，不改变主面板扫描和转发 |
| 可见类别 | 全部 | 可筛 Space、其他终端、其他进程、未知 |
| 进程名规则 | 空 | 文本或显式 regex；包含/排除需可辨识 |
| 端口规则 | 空 | 单端口及闭区间，如 `3000,8000-8999`；包含/排除需可辨识 |
| 扫描间隔 | 先沿用 Live Ports 的 4 秒 | 可配置且设上下限；远端开销和后台节流需测量 |

过滤条件的组合语义必须可预测：不同字段 AND；同字段多个允许项 OR，排除项优先；空规则不过滤。进程名缺失是 unknown，不能悄悄按空字符串或匹配成功处理。正则语法错误、无效端口、反向区间或越界不保存为有效规则；保留上次有效设置并显示错误。正则应防范灾难性回溯，不在 UI 线程对无界输入反复执行；具体可用安全引擎或限制须先验证，不能仅靠长度限制宣称安全。

## 4. 转发与进程操作

- 为远程端口提供独立的“启用转发”“关闭转发”和“打开浏览器”；建立转发不自动打开浏览器。默认绑定 `127.0.0.1`，不提供公网暴露的隐式行为。
- 创建前可指定本地端口，校验 `1..65535`；占用时显示冲突，不静默更换。只有用户主动要求替代端口才分配其他端口。允许用户修改映射：先校验并明确停旧/启新结果，失败时如实显示实际状态，不承诺无中断。
- 从可信的 Herdr machine 配置解析 SSH target，使用参数数组，不拼接 shell 命令。确认远程监听地址是否可用：远程 loopback、通配、指定地址、IPv4/IPv6 不可全部假定为 `localhost`；地址不可安全映射时提示而不是偷偷换目标。
- 转发交给可识别的 herdr-core 终端，进程退出、SSH 失败、本地端口占用和超时要可见。不能仅因本地端口监听就断言属于刚启动的 SSH：须核对进程身份与退出状态，避免竞争条件和错误成功；清理只针对本 mod 确认拥有的转发。
- 重启 App 后发现和恢复**已有运行中**的转发；不会在启动时自动新建。若兼容 Space Ports 旧标签，只在确认身份和所有权后识别，禁止误杀其他进程；标签格式、不同机器同端口和冲突须测试。
- “停止转发”和“终止监听进程”是独立操作。终止监听进程需确认，展示 machine、PID、程序和端口；执行前重新确认 PID/身份，防 PID 重用。无权限或信息不足时禁止该操作。关闭筛选、隐藏条目或卸载 UI 均不触发任何停止操作。

## 5. 侧栏与更新

侧栏展示不作为独立扫描器：消费同一份发现与筛选视图，避免双重扫描和不一致。每个 Space 只显示确定属于它的记录，其他机器级端口不复制到每个 Space。开关只控制显示，不控制转发。

Herdr 的自带 Spaces mod 不提供任意注入槽位（需进一步验证）；若必须 clone 并替换，单独维护可选适配器，显式提示其不自动继承上游修复，并提供恢复原侧栏的步骤。不能假定原生开关或自动更新可行。个人 mod 使用独立名称和 shared key，避免覆盖原 Live Ports、Space Ports 和已有用户偏好。

## 6. 分阶段实现与验证

1. **技术验证**：在不更改现有布局/连接状态下确认 Herdr 当前 API、machine 无 Space 时能否枚举/执行、远程 `ss` / `lsof` 及进程身份信息、侧栏注入和 SSH 持久生命周期。失败时明确局限，再决定是否继续，不用静默替代。
2. **纯逻辑与扫描**：测试解析 macOS `lsof`、Linux `ss`、IPv6、多地址、多进程、缺 PID、权限失败、离线、超时、空结果和缓存过期；测试两种归属、重叠 checkout、机器隔离、TTY 与 unknown。
3. **筛选与 UI**：文本/regex、无效与危险表达式、区间边界、包含/排除、组合、持久化与切换；证明筛选不会影响原始快照与已建立转发。检查可访问性、键盘操作和窄窗口。
4. **转发**：用受控的临时本机及 SSH 测试环境验证启停、端口占用和竞争、失败、退出、重启恢复、网络断开、修改映射及未知所有权；不对真实服务执行终止操作。
5. **可选侧栏与安装**：验证开关、恢复和上游兼容。每个 mod 通过 `herdr-app check`（检查模式不得产生进程或文件副作用），并在实际 Herdr 窗口验收；本机和真实远端分别记录测试，不用 mock 冒充远端。

最终验收：默认不转发、不终止进程；打开面板可看到可发现监听记录及分类；切换归属与筛选不改变进程/转发；可手动设定本地端口并安全启停远程 SSH 转发；机器无 Space 的扫描和侧栏显示都可开关；离线、无权限、未知进程与失败均有真实状态。
